Nginx $request_body 为什么是空的？一个 proxy_pass 揪出真相

  • 一、问题不在 Buffer
  • 二、client_body_in_file_only 也救不了
  • 三、为什么 proxy_pass 可以？
  • 四、一个极简后端
  • 五、几个容易记错的地方
    • 1. client_body_buffer_size 不负责读取
    • 2. client_body_in_single_buffer 不是“防截断”
    • 3. client_max_body_size 和 buffer 不是一回事

最近接 Webhook 回调，需要让 Nginx 把 Post 请求体记录到日志里。

配置很简单：

log_format hook_log
    '$remote_addr [$time_local] "$request" $status body="$request_body"';

location /webhook {
    access_log /var/log/nginx/hook.log hook_log;
    return 200 "OK\n";
}

客户端发送：

curl -X POST https://hook.example.com/webhook \
     -H "Content-Type: application/json" \
     -d '{"event":"push","repo":"my-app"}'

结果日志却是：

10.0.1.5 [21/Aug/2026:14:30:00 +0800] "POST /webhook HTTP/1.1" 200 body=""

明明 POST 了 JSON，为什么 $request_body 是空的？

一、问题不在 Buffer

一开始尝试了：

client_max_body_size 10m;
client_body_buffer_size 10m;
client_body_in_single_buffer on;
client_body_in_file_only clean;

但还是空。

原因是：

这些配置解决的是 request body 怎么存，不负责主动触发 request body 的读取。

$request_body 只有在 Nginx 的请求处理流程实际读取了 body，并且 body 位于内存 buffer 中时，才能拿到内容。

而这里：

return 200 "OK\n";

请求很早就被 return 处理掉了，并没有进入需要读取 request body 的处理流程。

所以：

POST JSON
   ↓
Nginx
   ↓
return 200
   ↓
没有读取 body
   ↓
$request_body = ""

二、client_body_in_file_only 也救不了

这个指令：

client_body_in_file_only on;

只是让 Nginx 把 request body 保存到临时文件。

它并不会触发 body 读取。

而 $request_body 本身依赖内存中的 request body；如果 body 被放到了临时文件，应该关注：

$request_body_file

所以不要把：

client_body_in_file_only

当成“强制读取 body”的开关。

三、为什么 proxy_pass 可以？

最简单的解决方案：

location /webhook {
    proxy_pass http://127.0.0.1:9999;

    proxy_request_buffering on;

    client_max_body_size 10m;
    client_body_buffer_size 10m;
    client_body_in_single_buffer on;

    access_log /var/log/nginx/hook.log hook_log;
}

关键在于：

proxy_pass

让请求进入了 proxy 模块的处理流程。

默认：

proxy_request_buffering on;

Nginx 会先读取客户端的 request body，再发送给 upstream。

于是流程变成：

客户端 POST
    ↓
Nginx
    ↓
proxy_pass
    ↓
读取 request body
    ↓
内存 buffer
    ↓
转发给后端
    ↓
LOG 阶段
    ↓
$request_body 有值

四、一个极简后端

比如用 Go：

package main

import (
    "io"
    "net/http"
)

func main() {
    http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
        io.Copy(io.Discard, r.Body)
        r.Body.Close()

        w.WriteHeader(http.StatusOK)
        w.Write([]byte("OK"))
    })

    http.ListenAndServe("127.0.0.1:9999", nil)
}

启动：

go build -o hook-server main.go
./hook-server

然后：

curl -X POST https://hook.example.com/webhook \
     -H "Content-Type: application/json" \
     -d '{"event":"push","repo":"my-app"}'

日志就可以拿到：

body="{"event":"push","repo":"my-app"}"

生产环境建议使用：

log_format hook_log escape=json
    '{"remote_addr":"$remote_addr",'
    '"time":"$time_iso8601",'
    '"request":"$request",'
    '"status":$status,'
    '"body":"$request_body"}';

避免 request body 中的引号、换行等特殊字符破坏日志格式。

五、几个容易记错的地方

1. client_body_buffer_size 不负责读取

它只是：

读取 body 时使用多大的 buffer

不是：

开启 body 读取

2. client_body_in_single_buffer 不是“防截断”

它主要是让整个 body 尽量位于一个 buffer 中，使用 $request_body 时可以减少 copy。

3. client_max_body_size 和 buffer 不是一回事

client_max_body_size 10m;

表示：

最多允许客户端发送 10 MB。

而：

client_body_buffer_size 10m;

表示：

读取 body 时使用 10 MB 的 buffer。

body 超过 buffer 后，Nginx 可能使用临时文件，并不等于直接截断。

六、最终配置

对于一个简单的 Webhook 服务，可以直接这样：

http {
    log_format hook_log escape=json
        '{"remote_addr":"$remote_addr",'
        '"time":"$time_iso8601",'
        '"request":"$request",'
        '"status":$status,'
        '"content_type":"$content_type",'
        '"content_length":"$content_length",'
        '"body":"$request_body"}';

    upstream hook_backend {
        server 127.0.0.1:9999;
    }

    server {
        listen 443 ssl;
        server_name hook.example.com;

        location /webhook {
            proxy_pass http://hook_backend;
            proxy_request_buffering on;

            client_max_body_size 10m;
            client_body_buffer_size 10m;
            client_body_in_single_buffer on;

            access_log /var/log/nginx/hook.log hook_log;
        }
    }
}

总结

这次踩坑最值得记住的不是：

“Nginx 不转发就不读 body。”

这句话太绝对。

更准确的是：

Nginx 不会因为 access_log 使用了 $request_body，就自动读取 request body。必须有请求处理流程实际读取 body；而 $request_body 需要 body 位于内存 buffer 中才能使用。

对于 Webhook 这种场景：

return 200
    ↓
不会主动读取 body

而：

proxy_pass
    ↓
读取 body
    ↓
转发给轻量后端
    ↓
$request_body

所以，如果你需要在 Nginx 日志中记录 Webhook Body，一个简单可靠的方案就是：

proxy_pass + proxy_request_buffering on

仅此而已。
